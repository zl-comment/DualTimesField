# 外部评审简报：NEM 三区域电价预测能否用 agent 提升——完整尝试史与 R25 待评方案

日期：2026-11-19。用途：交给外部评审（Claude）评估 R25 方案的可行性。
本简报自包含，不需要访问源仓库。文末列出希望评审回答的具体问题。

## 1. 任务与评估体系

- 任务：澳大利亚 NEM 三区域（NSW1/QLD1/TAS1）日前电价概率预测。
  每小时滚动起点、提前 24 小时、输出五分位（q05/q10/q50/q90/q95），
  目标为区域参考价 RRP（$/MWh，可为负）。
- 指标：QS = 2×五分位平均 pinball（主指标）、MAE（排序后 q50）、
  RMSE、覆盖率与区间宽度。先区域内平均、再区域等权。
- 数据纪律：as-of 快照（预测 run 按"发布时间 ≤ 起点"选择）、
  无泄漏输入管道（已审计）、训练统计只用训练期。
- 折结构：训练 2015→2022-01；选择 2022H1；开发评估 2022H2
  （181 起点/区域，543 总）；正式测试集 2023–2024（17,521 起点/区域）
  **保持关闭**——只有通过开发预注册门的 arm 才能开一次。
- 全区域门（历史沿用）：对 identity 和上最佳配置，三区域 QS 与 MAE
  同时严格改善才算通过。

## 4. 已确立的结论

1. 选择机制（准入合同、迭代、新鲜证据、账本）在"两操作空间"上
   逐一经预注册实验检验，均未增值；R23 的固定准入规则未被任何
   agent 机制超越。
2. 存在的收益（约 0.03–0.05 QS，TAS1 为主、QLD1 部分）来自操作本身，
   且区域/状态条件化（NSW1 从未受益；QLD1 是 QS 与 MAE 的取舍）。
3. 全区域门对保守策略结构性困难：不行动的差恰好为零而非负。
4. 正式测试集保持关闭（无 arm 过门）。
5. 证据指向决策层上游：候选预测器质量与操作设计。

## 5. 待评方案：R25 选择天花板预筛（已预注册，未运行）

**动机**：转向模型选择/路由（含 MoE 式）之前，先测"完美选择器"的
天花板；天花板小则方向关闭。

**开发折**（两折，评估期不重叠）：
- 折 A：train≤2021-01-01，选择 2021H1，评估 2021H2
- 折 B：train≤2022-01-01，选择 2022H1，评估 2022H2

**候选**（开发方法一律不参与）：
- 必跑：baseline_lightgbm、baseline_xgboost（每折重训，生产超参，
  seed 2026）；persistence-24h、周季节 naive（零成本）；
  chronos2_zeroshot（免训练推理）
- 算力允许时按固定优先级补：patchtst→dlinear→gatets→timexer→
  linear→mlp
- 排除：tabpfn（发表 QS 39.48 超机械阈值 35）、moirai2/timesfm
  （P 表点输出，无五分位 QS）

**流程**：每候选×每折×每区域训练/推理一次，对评估期预测一次并保存
（模型用完即释放，无常驻）；逐起点评分得到"起点×模型"分数表；
之后所有分析只读该表。

**参照与天花板**：
- R0 永远 LightGBM；R1 逐区域固定最优；R3 区域×需求状态分桶最优
  （分桶沿用 R23/R24b 定义，仅 as-of 预测需求特征）
- C1 逐起点上帝视角最优；C2 区域×月最优
- R2 集成：逐分位均值/中位数、top-3

**唯一判定门 G1**：C1 − R0 的 QS 改善 ≥ 0.30 且折 A、B 同时为正
→ 路由方向立项；否则关闭并写回顾。其余全部数字只报告不设门。
（门槛依据：开发折 identity QS≈39.28，R23 全部贡献 0.028；新方向
需要约一个数量级的余量。）

**五个消融**（全在分数表上，不重跑模型）：候选集来源；路由粒度阶梯
（R0→R1→R3→C2→C1 各级增量）；选择 vs 组合；折间稳定性；区域分解。

**防折外迁移加固**：配对差同时报中位数与四分位距（防尖峰主导均值）；
天花板与增量按需求状态分桶、实现价格带切片（看余量是否状态特产）。

**红线**：不碰 2023–24 测试集；主表与冻结档案不动；不在评估折上调
任何参数。运行记录仅存 git 提交号与配置副本。

## 6. 请评审回答的问题

1. G1 门槛 0.30 QS（相对开发折尺度约 0.8%，相对测试集尺度约 1.2%）
   是否合理？偏松还是偏紧？
2. 两折（2021H2/2022H2，两种市场状态）同正的规则，作为折→测试集
   迁移的最低要求是否足够？是否应加折？
3. 候选集（2 树 + 2 naive + chronos2 + 可选神经）能否充分代表动物园？
   机械排除 tabpfn/moirai2/timesfm 是否会给天花板带来系统性偏差？
4. R3（区域×状态分桶最优）作为"可实现硬路由天花板"的代理是否公平？
   沿用 R24b 需求状态分桶定义有无隐患？
5. 让 persistence/季节 naive 进入 oracle 候选集是否恰当（尖峰期它们
   常是最优，可能推高天花板但路由器未必选得到）？
6. 逐起点 QS 聚合（24h×5 分位平均到 origin 级）再取 argmin 的 oracle
   定义，是否会被极端价格起点主导？中位数与状态切片报告是否足以
   兜住这一风险？
7. 本方案漏掉的主要风险是什么（如候选预测误差的相关结构、树在不同
   训练窗的选择方差、chronos2 受限输入与树的可比性）？
8. 若 G1 过线，"状态条件硬路由/软组合 → 可发表方法（1–3% 相对改进 +
   显著性检验）"这条后续路径是否成立？
9. 有没有更便宜或更直接回答同一问题的实验设计？
10. 与文献近邻（MoiraiAgent 专家选择器、TimeCopilot 中位数组合、
    forecast combination puzzle）相比，本设计的定位与差异化是否站得住？
