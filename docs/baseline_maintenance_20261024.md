# 核心基线维护协议（2026-10-24，第一步）

本轮只处理影响现有比较结论的输入时间证据与适配问题，不开发 Full，不新增大规模模型搜索。主表初始提交为 8f21797；结果沿用 NSW1/QLD1/TAS1、72→24h、原始价格空间、原测试 origin。旧实验不覆盖，修复实验单独冻结。

## 执行顺序与预算

1. 核查所有原始外生 NPZ 的 origin/source_run/source_last_changed，原始小时观测 available_at，以及气价源字段/滚动窗口；记录可验证范围。LASTCHANGED 不是公开发布时间；缺少发布记录只能报告未证实，不能伪造完备审计。
2. TimesFM 开发诊断：只用 selection=2022H1，每地区固定等距 128 个 origin，seed2026；比较原 xreg+timesfm/ridge0、同模式 ridge1 和裸 TimesFM。原始输入、权重、输出保持一致；裸模型仅诊断，不以测试效果选择。若 ridge1 在三地区开发宏 MAE 改善且每地区退化不超过5%，才允许作为修复候选，必须在完整 selection 再确认同门槛，再冻结并运行全测试。无条件删除最差预测、按测试分数择优、事后扩搜索均禁止。
3. TabPFN：保持官方权重和原生产批次4096；检查非生产批次差异，若固定规范查询分块能消除任意子集调用的批次变化，修复调用契约。对完整生产路径不改变算法与数值的修复不要求重新训练；用真实开发样本和结构测试验证，不把抽样验证称为全量重放。
4. 核心对照固定 LightGBM、XGBoost、PatchTST；保留原版本配置/选择规则/产物哈希，不为了修复 TimesFM 而重训这些模型。当前是固定配置比较，不宣称完成公平 HPO。
5. 每批提交推送；必要重跑产物完成审计后才替换主表对应来源。历史档案加 superseded/限制说明，旧数字不得原地伪装成新实验。

## 验收边界

缺少真实发布时间不能通过增加任意固定延迟自动解决；未发现时间戳违规也不等于已证明无修订数据泄露。确有输入错误时需使所有受影响模型使用同一修复缓存重新评估，否则保留旧表并标记不可作严格实时结论。基础模型预训练重叠继续标为 unaudited。
