一、研究目标与更新边界
部署侧不训练LLM、不微调Chronos-2、不训练Agent策略、LoRA或价格输出头。
LLM可由API提供；不限定为当前旧本地qwen服务，也不假定旧服务仍可用。
Chronos-2沿用R12的冻结检查点及配置/权重SHA。Agent只更新工作流、提示词、工具契约、
skills和开发期规则；新的版本必须产生新的manifest，不能在评价期间覆盖原版本。
本版本不拟合残差、融合权重或校准器，也不使用LLM自由平移/缩放预测分位数。
若以后引入已成熟误差校准，单列“冻结权重＋统计适应”版本，不能混入当前免参数训练臂。
根据开发标签改skills属于方法开发/选择；不能宣称完全没有任务数据适配。
监督基线可以训练，训练成本和训练期须明确；Agent本身不因此获得训练权限。

二、为何旧主表不能直接替换一行
R13只统一了2023每日零点的目标样本，未统一信息时点、输入与训练预算。
已核实的代码差异：
1. 主表历史[O-72h,O)，R12历史[O-73h,O-1h)，R12另有O-10min输入截止。
2. 主表一般日历配置10项（含year_standardized），R12为九项闭式日历特征。
3. 旧Chronos adapter使用demand_std，R12使用原始total_demand_mw。
4. 主表强基线读取多个公共输入块，旧Chronos adapter明确未映射其中四个外生块。
   配置里存在某字段不等于模型实际消费该字段，必须记录适配器实际输入清单和指纹。
5. Full_joint使用额外成熟历史及误差记忆；不能仅凭相同72小时窗口称它为同信息对照。
因此建立新的协议ID和独立结果表；旧主表、R12失败判定和R13参考排名保持历史身份。

三、新公共预测任务（用于所有正式参与的新行）
地区：NSW1、QLD1、TAS1；时区：固定AEST/UTC+10，不使用夏令时。
O为每天00:00，目标为[O,O+24h)，每小时RRP，单位AUD/MWh。
输入截止c=O-10min，预测发布期限d=O-1min；快照在c关闭，之后API推理不得更新输入。
历史72个小时起点为O-73h,...,O-2h；只接受可用时间<=c的完整历史值，不补入O-1h实际值。
共同数值输入保持float64原始价格/需求及R12九项日历，字段名/公式/顺序由公共builder确定。
Chronos内部float32和内部归一化属于模型计算，不能改变公共原始输入契约。
监督模型如需标准化，只能使用训练期拟合的统计量，并保存各模型预处理状态；不得全数据拟合。
候选未来需求代理覆盖25小时起点O-1h,...,O+23h，沿用已公开的R12近似语义，不升级为官方真值。
Chronos预测25步后丢弃桥接首步；监督模型直接把同一历史映射至O,...,O+23h这24个目标，
如输入25步协变量可保留桥接条件，但不使用桥接真实价格作标签/特征。原24步模型不可机械错位复用。
所有模型必须逐值通过history_time、target_time、snapshot_id和共享原始输入指纹核验。
未来需求是截止时点已发行的预测，不是事后实际需求；训练样本也必须按其各自origin恢复发行版本。
数据availability仍为代理时明示archive_proxy；只能对真实已收取版本声明observed_receipt。

四、把“同输入”与“同信息访问权限”分开
I0基础信息：历史72小时价格＋需求＋九项过去/未来日历。
I1数值信息：I0＋R12同版本25小时TOTALDEMAND代理；所有同I1模型共用逐值相同数组和缺失状态。
I2文本信息：I1＋一类有历史版本证据的公告来源＋经过批准的事实到数值映射。
首个候选来源为AEMO Market Notices，但当前尚未完成语料快照、历史通道和数值映射审计，
I2不是已可执行/已有效的输入档位。无合法映射时文本只能用于解释，不宣称它改变了预测。
不要把发电不可用MW塞入需求MW，也不要凭“风险高”编造价格倍率；未建立历史语义的新0/1事件
通道不因Chronos支持协变量就自动准入。映射须在看评价价格前固定并通过接口与事实核验。

数值模型比较：同一个I0或I1中的模型获得完全相同的原始数值数组。
Agent机制比较：B2/C/D有同一个I2候选来源池、快照、工具权限、字段白名单和最终输入适配器；
检索顺序、事实抽取和实际选中的合法证据可能不同，这正是被检验的干预。
不能同时要求这些组最终输入完全相同，又把数值差归为检索收益；若最终输入相同，冻结预测器
输出应相同，此时仅能比较成本、时延、成功率和事实处理质量。
未来若跨预测器比较I2，使用预先固定的公共事件编码；或将D最终事实包逐值回放给其他预测器
作单列诊断，并计入上游LLM成本，不能把此臂叫作不依赖LLM的基线。

五、两张主实验表及对照组
表N：同数值输入系统比较。首轮最小集合为Chronos-2、LightGBM、XGBoost、PatchTST、DLinear，
分别在I0与I1运行；同一模型的I1-I0说明该数值信息在该模型中的收益。
监督基线必须按新的时间间隔、日历和特征重建训练样本并重新拟合；不是重评分旧test.npz即可。
Full_joint独立标记extended_history_reference。若要纳入严格同信息表，需另实现受限历史版本，
但那是一个新方法版本，不冒充原Full_joint。其他主表模型待适配器通过后再扩充，不删失败模型。
只有点预测能力的模型进入MAE/RMSE列；不得伪造五分位QS。

表A：相同冻结Chronos-2的Agent贡献比较。
A0：I0，固定数值流程，无LLM。
B1：I1，健全固定数值流程，无LLM；R12 B的对齐继承对照。
B2：I2，健全固定解析/版本/检索流程，无LLM，不故意忽略公开字段或有效版本。
C：I2，API LLM＋固定检索、抽取和核验顺序。
D：I2，同一个API模型＋同一skill集合，但可在预算内自适应检索和补查。
两种LLM流程共用模板、字段契约、可访问事实、预算上限及失败处理，仅编排策略不同。
B1-A0检验需求信息；B2-B1检验额外来源＋固定处理；C-B2检验语言抽取；D-C为Agent主要对比，
D-B2为必要实用参照。D-A0是总系统差异，不能独自证明Agent贡献。
LLM不得直接生成最终24×5价格数组；发布必须引用预测工具生成且输入校验通过的forecast_id。
不人为安排复杂度让固定流程失败；若确定性程序能准确完成相同任务，应把它作为强对照。
I2前置尚未满足时，只允许实现接口和合成时点测试，不启动新闻Agent价格矩阵。

六、开发、选择与评价时期
2023全年作为流程/skills开发与选择期，已暴露的R12/R13结果可用于提出新假设，但须记录版本。
监督模型训练目标时段在2023-01-01前结束，2023用于与Agent相同的开发选择；评价候选为2024全年。
训练最早可从2015开始，但I1实际可用起点必须由版本/语义覆盖审计确定，不能根据测试分数选择。
同信息档的监督模型共用冻结训练/选择样本manifest；不能用未来真实需求填补历史预报缺口。
当前不能保证既有档案覆盖I1的训练期，缺口需明确报告，不能沿用旧填充缓存冒充已对齐。
所有训练/选择样本按其24小时标签区间做边界清除，不能只看origin年份；反馈以真实到达为准。
2024已被其他研究查看，因此只称“固定2024历史回顾评价”，不称盲测、独立确认或排除预训练污染。
2024覆盖审计不等于已执行新的2024预测；当前没有开始该矩阵。
最终确认使用模型/工作流冻结后的未来时段，开始/结束日期另行固定，不能边看分数边延长。
本设计没有请求创建定时采集、自动化或未来任务。

七、版本化Agent与skills
服务端模型由API_MODEL_ID与可用的固定版本标识确定；不得依赖会静默变化的latest别名。
如果服务不提供不可变版本，记录其限制、实际返回模型ID/指纹以及调用时间，并按版本漂移分段。
密钥仅从环境/秘密配置读取，不写进Git、输入manifest或wire日志；本轮不探测和调用端点。
AgentVersion记录workflow_id/version/hash、system_prompt_hash、tool_schema_hash、每个skill版本/hash、
输入/映射/评分版本、Chronos配置与权重SHA、API模型与采样参数、全部资源上限。
四个项目内skill契约见r14_skill_contracts_20261102.txt；它们是目标Agent的设计，不是已安装Codex技能。
开发阶段可以更新；评价阶段全部冻结。运行中记忆只存截止时点已可见证据，不让评价标签更新skill。
C/D共享技能内容，用固定/自适应编排区分；新增技能时明确是新候选，不只给D暗中增加能力。
不让当前日期网页、任意Python/shell、任意文件路径或未过滤数据库成为Agent工具。

八、防止读取未来与失败处理
工具服务绑定不可变snapshot_id和c，LLM不能通过参数修改cutoff、region或读取其他起点未来资料。
先在权限层裁可见版本，再检索排序；引用必须解析到允许正文中的确切字节片段。
新闻正文是证据，不是指令；撤销/替代关系只按当时可见证据解析，不用后来公告改写过去。
推理进程只挂载inputs；labels与其他未来文档在文件系统/服务权限层不可读，不能仅靠prompt约束。
预测按origin顺序或相互独立执行；缓存不得从更晚origin回流；无跨region/origin的模型信息混合。
当前版本无预测误差反馈决策。未来若研究反馈，必须另设版本并按标签到达时点成熟后开放。
这些措施隔离外部未来数据，但不证明API LLM或Chronos预训练没有历史知识；历史结果披露该边界。

每个origin先生成A0和可用的B1。B1来源缺失按冻结规则回退A0；C/D失败回退B1（B1缺失时A0）。
回退输出逐值保留，记录failure_reason、attempted_input_hash、effective_input_hash、fallback_to。
监督I1模型的缺失策略在训练前固定：可使用同架构I0回退，且保留全部计划样本。
公共可评分集合由合法I0历史与标签定义，不能由“所有模型都成功”的交集定义。
某模型仍有未解决预测缺口时，不从其余方法删除该日期；报告缺口且不授予完整主表排名。
无A0或无完整标签的单元进入计划清单/缺失率，分数仅代表公共可评分部分，不能伪造预测。
实际前推超出d为发布失败，即使后来返回有效输出也按预定回退/缺失记账。

九、评分、资源与结论规则
原始输出归档，所有Q表采用相同逐时分位排序作为评分操作，q50用于MAE；不裁剪负价/尖峰。
QS=2×mean pinball，五分位[.05,.10,.50,.90,.95]，不将五分位代理QS称为精确CRPS。
附原生分位评分和交叉数；排序不由LLM控制，不进行任务拟合校准。
主指标QS，次指标MAE、地区pooled RMSE、C80/C90、区间宽度、失败/回退/发布率、实际成本与时延。
先每个模型运行/seed按地区等权宏平均，再汇总重复运行；不先平均预测，不挑最好的API运行。
确定性A0/B1/B2只执行一次；C/D各三个API重复使用相同设置，不把重复当新增独立日期。
监督模型三个训练seed单独报告；不能与API重复的含义混同。
采用共同日期轴、三区同步7日移动块bootstrap（2000次）估计配对损失差；重复运行先在日内平均，
不把API重复或同日地区拆成独立bootstrap样本。超参数/skill选择不能接触评价分数。
排名按未舍入宏均值并列计数，P表不参加QS；raw/消融放附表，不重复充当独立方法。

信息收益检查（新运行B1对A0）沿用R12规则：宏QS至少降低1%、95%相对差上界<0，宏MAE恶化<=1%，
各区QS恶化<=2%，宏平均地区绝对覆盖偏差及每区C80/C90偏差增加<=1个百分点，
每区来源、预测、共同评分率>=95%，无未回退预测缺口。旧R12仍NO_USEFUL_GAIN，不被本设计改判。
Agent有效性主比较D-C采用同一损失/覆盖保护，并要求D-B2不退化及明确的事实/输入差异证据。
若预测无增量，仅成本下降或可用率改善，单独报告效率收益；不自动改称精度成功。
预算拟定上限：C/D每region-origin最多3次API请求、6次外部只读工具调用，无隐式重试，
各共12000输入tokens/3000输出tokens；实际计数包含重发、schema失败和prompt，不能只计成功调用。
截止到发布的完整流程上限480秒，位于540秒可用窗口内；公共A0/B1计算也计入流程总时延。
这些是设计上限；实施前需用合成/无标签接口检查验证可行性，不能为追分中途改变。
B2不强制浪费调用；同上限不宣称实际算力相同。共享底座/缓存分别报告边际成本与独立部署成本。
API服务、固定模型版本、费率与总金额上限尚未指定，运行矩阵/成本清单需在调用前补齐。

十、实现顺序与交付
M0：公共as-of输入builder及两张表的契约；复用R12读取逻辑而不修改其归档。
    通过历史窗口、桥接目标、九项日历、原始单位、未来文档隔离、标签不可读等测试。
M1：训练期发行档案覆盖审计；实现I0/I1适配器，先完成数值对齐比较及原有覆盖问题诊断。
    当前新I1训练快照未准备，不能启动监督基线重训。
M2：一个I2来源的归档版本和语义映射；验证引用/单位/版本提取正确性，不先让LLM猜价格。
M3：API传输适配器、四个版本化skills、C固定流程与D自适应流程、配对回退及成本账本。
M4：在新执行分支提交完整配置/源码/数据指纹/日期/预算后，运行固定历史评价；之后才计划前推确认。
M2可以先完成无标签的接口/事实测试，但不因为实现了工具就自动越过预测收益和覆盖条件。
每个新增批量实验按AGENTS.md另建独立执行分支；本分支提交的是设计，不是假装完成上述实现。
目前未就绪项仅是实际工程/数据项，不是另加用户审批流程；已有授权范围内可继续准备它们。
