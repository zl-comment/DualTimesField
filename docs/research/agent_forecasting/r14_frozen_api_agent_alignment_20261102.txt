4. 必需三个角色，只新增两条预测路径
BASE：现有主表chronos2_zeroshot，复用已核验预测。
FIXED：同一冻结预测器＋与Agent相同可访问来源＋健全固定检索/解析/版本规则，无LLM。
AGENT：同一预测器＋同一来源池，API LLM用版本化skills自适应检索、抽取、核验和调用工具。
AGENT对原25行看整体排名；AGENT对FIXED看语言处理与编排的整体增量；
FIXED对BASE看新增信息＋固定处理增量。不能只用AGENT优于BASE证明Agent有效。
可选的同LLM固定流程SINGLE_LLM留作后续机制消融，不是第一阶段必跑项。
FIXED和AGENT共用快照/来源池/允许字段/适配器，不故意削弱固定程序；
检索与选中的证据可以不同，最终输入相同时冻结数值输出也应相同。
主表各方法本来就有信息范围差异。Agent增加公告等信息时明确标注input_scope，
总体排名属于系统比较，不宣称严格同信息/同训练预算，也不要求重训原基线。

5. Agent开发与skill版本化
流程：当前起点快照→按需检索→事实与引用抽取→版本/时间/单位核验→构建允许输入→
冻结预测器→forecast_id及解释。LLM不手写24×5价格、不自由平移/缩放分位数。
四个skill：evidence_retrieval、event_extraction、version_resolution、forecast_request。
每个release保存API模型身份、参数、工作流、prompt、skills、工具schema、输入映射、
预测器与评分版本/hash。开发阶段可改结构/skill，评价阶段锁定，不在线改权重或拟合校准器。
先接一个有合法来源及数值接口的信息源；需求资料可复用，文本可选可追溯官方公告。
没有经验证的事实到数值映射时文本只用于解释，不宣称带来预测增益；发电MW不能冒充需求MW。
实际映射/API模型/skill文件尚待实现或固定，这是Agent自身开发，不是重做基线的理由。

6. 未来信息与失败处理
现有PredictionView不含标签，但整年view包含以后起点的历史，不能整份暴露给LLM。
coordinator从旧缓存拆出当前region-origin输入及BASE输出，scorer独占标签。
Agent不能读取带actual的test.npz、整个缓存目录、全时段BASE预测或其他origin的快照。
工具端绑定region/origin/cutoff=O，先筛当时可见正文版本再检索，不接受LLM修改截止时点。
不开放实时网页搜索、任意shell/文件路径；未来缓存/记忆不向过去起点回流。
这些约束阻止外部未来读取，但不能证明API模型没有预训练历史知识。
FIXED失败回退BASE；AGENT失败回退FIXED，FIXED不可用则BASE，逐值保存并记录原因。
不删失败日期，不使用评价误差更新skill。原标签/起点不可因Agent可用性改变。
