Only the external process supervisor and reporting change. The original R20
replay, policy, predictors, skills, budgets, 180-second deadline and 30-second
API timeout are unchanged. Seed 2026; full test 2023–2024; each region has
17,521 origins, total 52,563. Each origin forecasts the next 24 hours.

NSW1, QLD1, TAS1 run in independent OS processes. Each executes the original
single-region replay in chronological order with its own append-only ledger,
model registry, committed bundles, process lock, progress and manifest. The
original ledger snapshot already filters on region and outcome maturity.
Historical analog cohorts also require the current region and mature targets.
No region can access another region's output or future feedback.

Three processes share the existing Kev service on GPU6 and place separate
Chronos instances on GPU7. LightGBM retains four threads per process. No new
GPU allocation or serving model changes. GPU sharing can limit speedup and
change latency. Each region keeps its own original timeouts and fallback rules.
Forecasting source is byte-identical; process scheduling is not a claim of
universal numerical or LLM-response equivalence. Development verification
compares predictions and decisions against the previous serial run.

Each region scores only after all its own requested predictions are committed.
No metrics are fed to another worker. The supervisor audits completed regional
artifacts, validates common frozen identities, and only then writes the final
three-region report. Aggregation uses the same equal-region metric mean as the
serial runner; percentile timings are never averaged across regional reports.
An incomplete/missing/failed region cannot produce a complete aggregate.

The parent progress.json has total and per-region counts and worker PIDs.
Each region has report.json, run_manifest.json, progress.json, feedback.jsonl,
origins/ and a unique execution_audit timestamp. Worker logs are at root as
NSW1.log, QLD1.log, TAS1.log. A failed worker interrupts other owned workers;
all committed prefixes remain recoverable, without automatic policy changes.

Full-test reuse and model pretraining overlap limitations remain those of the
original R20 experiment; this scheduling change does not create a new blind test.
