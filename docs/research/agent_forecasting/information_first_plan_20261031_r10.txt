3. 四个设计差距的具体修改

差距一：信息大多重复。
修改：新增的唯一信息是未来需求预报，不是再次加入历史需求。先由固定程序构造输入，
      完全不调用 LLM，做 B−A 配对比较。每个新增值必须有来源行、vintage、目标小时和时点依据。
完成依据：相同基础输入仅在允许的未来需求通道上不同，且全计划网格评分达到第 8 节规则。

差距二：没有成熟反馈。
修改：增加追加式 PredictionLedger 和 OutcomeLedger，记录已发布预测、实际标签及其到达时间。
      到达的逐小时真实价格可成为后续历史输入；整条 24 小时预测的误差只在其标签全部成熟后计算。
      首轮仅监控，不让 B/C/D 读取误差选择动作、窗口或来源，避免混入另一个收益机制。
完成依据：未成熟标签不能进入误差记录，过去记录不被修订后覆盖；第 11 节单独定义反馈研究。

差距三：输出修正太粗。
修改：从新流程移除五选一价格平移/缩放。逐小时更新合法输入，再由同一个冻结预测器输出分位数。
      Agent 只能返回来源引用、有效版本与工具生成的 forecast_id，不能返回价格幅度、风险倍率。
完成依据：相同最终输入具有相同数值输出；没有对 24×5 结果做自由修改、排序修复或价格裁剪。

差距四：基础模型描述不完整。
修改：由输入清单生成 BaseInputManifest，明确 72 小时历史价格和需求、九项过去/未来日历、
      新增未来需求字段、未接入字段、单位、可见截止和输出目标。C/D 使用相同清单。
      提示词区分“预测器已使用的事实”和“可以补查的事实”，不要求模型必须找到一个修正动作。
完成依据：描述与实际输入字段一致；没有把近期均价高于基线直接定义成基线低估。

4. 比较组与因果归属

A：冻结数值基线。历史价格、历史需求、日历；没有未来 TOTALDEMAND。
B：健全固定流程。A + 唯一未来需求通道；含合理的目标对齐、版本、重复和完整性处理。
C：固定检索顺序 + 同一个 LLM 的固定核验流程；与 D 相同候选来源、工具、输入、预算上限。
D：同一个 LLM 自适应选择检索/核验顺序；最终仍执行与 B/C 相同的适配器和预测器。

S1 只运行 A/B：B−A 是该数据源和固定输入映射的信息增量。
S2/S3 才比较 B/C/D：C−B 是固定语言处理增量；D−C 是主要自适应流程比较；D−B 必须同时成立。
D−A 只表示整个系统总差异，不能独自支持 Agent 有用。
相同预算指相同上限，不强制 B 浪费调用；同时报告实际请求、tokens、证据字节及耗时。
不得让 B 故意遗漏第三镜像、使用已撤销数据、只读旧版本或忽略公开元数据以制造 D 的优势。
同一数据源的普通排序/去重能解决的问题直接交给固定程序，不要求 LLM 再做一遍。

5) CoverageInventory：只用元数据统计 2022 全年固定每日网格的候选完整率与缺失原因。

为避免预测发布时点落在被预测小时之后，新的公共时间约定为：
- 目标开始 O = 每日 00:00 AEST，预测区间 [O,O+24h)。
- 输入截止 c = O−10min；正式发布期限 d = O−1min；所有臂使用同一快照。
- 历史窗口固定为 [O−73h,O−1h) 的 72 个完整小时，最后一小时应在 c 前已可见。
- 数值模型从 O−1h 开始预测 25 步，第一步作为时间间隔丢弃，保留后 24 步供评分。
  所有臂日历覆盖 25 步；只有 B/C/D 需要相应未来需求，同 vintage 须有 50 个半小时值。
- S0 必须验证源能否在 c 前覆盖该 25 小时范围以及历史输入的实际到达情况；缺失不缩短目标。
- 半小时首目标须不晚于 O−30min，末目标须不早于 O+24h，且中间 50 个精确末端全部存在。
  新 run 可能已不含桥接小时，因而“最新完整 25 步版本”可能比只覆盖目标 24 小时的最新 run 旧。
  记录所选 run 年龄、晚于它但不完整的 run 数，轮询保留此前完整正文；不将其简称为最新预报。
  “仅桥接小时缺失”和“评分目标小时缺失”分别计数；不能根据后续收益临时改填充或拼接规则。
- 这是相对 r9/M0 的显式时间接口变化：新 A 必须重新生成，不能直接使用 r9 的 52.07/30.33 作对照。
  历史回放也用同一时间规则，但历史输入 available_at 的代理性质仍需披露。

预先确定路线，选择只由数据与时点审查决定，不看预测分数：
H：若存在保留 vintage 的历史原始档案、语义成立且每地区预计完整率 >=95%，可做 S1-H 历史探索。
P：若任一 H 条件不成立（包括历史仅部分可恢复、完整率不足），但可建立真实收取路径，
   走 S1-P 前推；先做连续 7 天不评分采集验收。
   验收日期在采集前冻结，三个地区分别完整 >=95%；七日只有七个日单元，等价于各地区全部覆盖。
   只要一天缺失便如实记录未达此运行准备标准，不按分数延长或替换日期。
若两条路径都不可用，停止并报告数据可得性阻断，不将其写成 TOTALDEMAND 无预测信息。
顺序固定为：全部 H 条件满足→H；否则 P 条件满足→P；否则阻断。所选路线在评分前提交。
H 路线评分不通过后，不允许自动改走 P、换时点或换风光来源作为本轮补救。

8. 统一评分、实际收益门槛与停止规则

主指标：QS = 2 × mean_{origin,region,hour,q}(pinball_q(y−qhat))，
q = [0.05,0.10,0.50,0.90,0.95]，单位 AUD/MWh；先按地区求均值，再对三地区等权宏平均。
次指标：q50 MAE、逐分位损失、有符号偏差、C80/C90、区间宽度、来源覆盖/发布率、时延与成本。
主价格标签采用与原项目一致的小时 RRP 定义；前推时保存选定标签版本及完整到达时间。
前推逐目标小时以该小时结束+7×24h 为封存截止，取此前完整收到的最后一个合法标签版本；
后续价格修订只在附表展示，不重写主分数。最后起报结束后等待最后一个目标的封存截止再评分。
历史 H 使用评分前固定的本地标签快照；若是事后最终修订，同样披露，不冒称第七天实收版本。
主配对分数使用共同具有 A 与完整 24 小时封存标签的单元，各臂共用同一掩码；B/C/D 失败回退仍计入。
缺 A 或缺标签无法计算误差，不造值，但仍进入计划总数和缺失清单。每地区共同可评分率须 >=95%，
未达则报告 DATA_OR_EXECUTION_BLOCKED，不能把剩余小子集的好分数当全网格通过。

配对推断：
- 使用共同日期轴的连续 7 日移动块 bootstrap，2000 次，固定 bootstrap seed=20261031。
- 每次同步抽取三地区、各臂及所有重复；一条 origin 的 24 小时先整体保留，不当作 24 个独立样本。
- 同一次重采样中重新计算相对差 (QS_new−QS_ref)/QS_ref，报告双侧 95% 百分位区间。
- seed 重复先在相同日期/地区上平均各次损失与指标，不能增加样本数；分 seed 结果单独描述稳定性。
  不先平均分位数再评分，后者会变成未声明的集成预测。
- 日期标签缺失不压缩后拼接为连续日；缺失掩码随日期块移动。样本不足时报告不可可靠推断。

S1 进入 S2 的计划规则（均需满足）：
a) B 相对 A 宏 QS 至少下降 1%，且相对差的 95% 区间上界 <0。
b) 宏 MAE 劣化不超过 1%；任一地区 QS 劣化不超过 2%。
c) C80/C90 与各自标称覆盖率的绝对距离，宏平均及各地区相对 A 的恶化分别不超过 1 个百分点。
d) 每地区来源完整率、预测可用率及共同可评分率均 >=95%；发布及时性另列，不用子集掩盖失败。
1% 是本计划的最小实际收益要求，用于约束继续投入；不是从此次待评分结果估计出来的阈值。
“点估计改善至少 1% 且区间排除零”不等于“区间保证改善至少 1%”，报告必须区分这两种表述。
宽度必须报告，由 QS 与覆盖共同解释；不另设一个可通过无限放宽区间满足的目标。

结果分类：
- PASS_INFORMATION：以上成立。H 只获得探索支持；P 获得该固定前推时段的支持。
- NO_USEFUL_GAIN：点效应未到实际阈值或保护指标失败，结束本候选本轮流程。
- INCONCLUSIVE：点效应满足但区间未排除零/样本不足，按固定预算结束，不宣布普遍无效。
- DATA_OR_EXECUTION_BLOCKED：无法完成预定数据或执行，独立于科学假设结论。
不根据结果调整阈值、追加年份、换区域或临时增加 seed；科学规则只在完成预定数据后判断一次。

9. S2：先证明 Agent 真的改变了有用输入

只有 S1 通过，才建立 research/agent-totaldemand-agent-mechanism-<实施日期>。
先做来源处理与输入差异研究，不一开始再跑三个地区×三个 seed 的价格矩阵。

事实集：从已收取、未按电价挑选的来源链中，按时间顺序抽取最多 30 个真实 case；
按源原生支持的“普通更新、同 target 多版本、跨日覆盖、重复、缺失、冲突”分层，每层最多 5 个。
不足的类型记缺失；不改正文、不制造第三镜像故障来冒充现实事件。工程反例单列为合成测试。
以 case 身份 hash 排序固定 10 个开发 case，余下最多 20 个封存；共享版本链不能跨两边泄漏。
如没有足够真实复杂 case 或开发/封存类别分布不足，报告证据稀疏，不扩大到看见成功为止。

TOTALDEMAND 没有原生公告撤销语义；“撤销”在本候选中标 NOT_APPLICABLE。
本阶段的关联任务只包括同产品的 run、版本、target、地区及权威元数据，不凭空加入公告信息。
需要市场公告/外部事件才能影响数值时，必须为该来源另外完成语义与时点审查和新的 S1，
不能在本阶段直接赋予“停机公告→涨价”规则，也不把已经进入负荷预报的影响再次相加。

B/C/D 使用同一输入快照与允许访问的候选来源全集；固定 C 检索计划合理利用元数据和预算。
C/D 固定同一模型身份、temperature=0、prompt、三次总 LLM 请求上限和四次工具调用上限。
C 按预定顺序批量获取后核验，D 可根据前一步结果调整后续查证；每次访问都计入预算。
S2 固定 seed=2026；不做模型/提示词搜索。开发 case 用于协议调试，封存后不再改 prompt。

每个 case 保存：正确来源集合的依据、候选版本、所选行、可见性、输入 tensor/hash、失败原因、
调用/字节/token/时延。事实标签须依据官方主键或可复核源证据；缺少依据时保留 unknown。
多 Agent 一致意见不当作真人金标准；需要人工判断的歧义留为未定，不强行标对错。

S2 的继续规则：
- 若 D 在所有封存真实 case 上逐一与 B 相同，或在所有 case 上逐一与 C 相同，停止当前自主性扩展。
  注意量词顺序：case1 的 D=B、case2 的 D=C，并不表示 D 与某个固定臂在所有 case 相同；
  这种选择性处理可能产生增量，不能错误地要求 D 在每个 case 都创造第三种输入。
  这只是当前有限来源和预算内未见增量，不再写“固定规则在所有场景已足够”的全域结论。
- 若 D 有额外有效输入差异，须给出至少一个封存真实 case 的来源与目标对齐证据；该见证仅说明
  机制存在，不证明普遍优越或价格收益。不得同时发生 D 非法使用截止后信息的情况。
- 让 B/C 对 D 最终取得的证据集合做离线处理回放，区分“找到证据”与“解析同一证据”差异；
  该回放是归因诊断，不替代在线预算下 B/C 的主结果，也不据此修改冻结基线。
- 每个封存 case/臂分类为“正确有效输入、已核验错误输入、回退或失败、unknown”四种互斥状态。
  unknown 不计成功；如果连期望来源都无独立证据，该 case 所有臂的正确性均为 unknown。
  D 相对 B、C 各须至少有一个已核验正确输入增量，D 正确有效输入总数不少于两者各自总数，
  且已核验错误输入总数不多于任一对照；不是以小样本的“差异不显著”代替不劣化。
  非法使用截止后信息为明确失败。以上与合法输入差异、预算可行同时满足才设计 S3；
  unknown 太多或差异不足时记证据不足并结束，不靠单个见证掩盖其他已核验错误。

10. S3：在新的前推时段检验 Agent 的价格收益

建议分支：research/agent-totaldemand-agent-forward-<实施日期>。
S3 使用 S2 结束且代码、prompt、配置冻结之后的新 112 天；不得复用 S1-P 的评分窗口。
每日三地区、相同 O/c/d 和 24 小时标签；A/B/C/D 同快照、同数值模型、同字段。
C/D 使用 seeds=[2026,2027,2028]；A/B 只运行一次，共享相同输入的数值输出可以按 hash 缓存。
温度零下的 seed 重复只检验执行稳定性，不当作三个独立模型或三个独立样本。

唯一主要自主性比较为 D−C：宏 QS 至少下降 1%，95% 区间上界 <0；
同时要求 D−B 达到同样的 QS 标准，且对 B/C 分别满足第 8 节 MAE/地区/覆盖保护。
这两个条件共同定义成功，不选择其中显著的一项替代另一项；D−A 仅作为系统效果补充。
系统部署还要求 D 相对 A 的宏 QS 点估计至少改善 1%，且对 A 满足同样的保护指标；
若 B/C 在前推期自身退化，仅胜过 B/C 不能达到部署条件。该系统条件不能替代自主性对照。
采用同一配对块统计规则；三个 seed 逐个“通过”不是成功条件，不按好 seed 报结果。
每地区 >=95% 的计划单元须按期限发布；记录所有回退、超时及系统缺失。
超时回退只使用同一截止前已完成的 A，不接入已训练 LightGBM，不重试直到获得好动作。
所有臂最终展示总体及分地区结果；不得事后按真实价格、尖峰或地区筛选主结果。

通过后才能声称“在该来源、固定模型、预算和前推窗口内，Agent 比已冻结固定流程有增益”。
不能外推为所有电力市场、所有时段、更换模型仍然成立，也不宣称首个电价 Agent。
未通过则保留已证实有效的 B 数据接入，归档 D 的失败或不确定结果，不追加第四轮补救。

11. 成熟反馈的建设与后续独立验证

从 S1 开始建立账本，但只允许如下固定状态更新：
PredictionLedger：origin/target、输入截止、发布时刻、输入/output hash、来源、模型/prompt 身份。
OutcomeLedger：target、实际价格、标签完整接收时间、版本、首次观测值、第七天封存值。
FeedbackLedger：按标签可见时间推进，仅在整条 24 小时标签已到达后记录整条预测误差；
第七天封存版本到达后生成最终评分。禁止把未来完整标签表直接 join 回预测输入对象。
依赖后续修订的价格只在收到后进入新记录，不改写过去决策时能看见的反馈。

首轮不让 Agent 读取 FeedbackLedger；因此不能把“有账本”声称为已经实现效果自适应。
若 S3 支持自主性，再单独提出反馈实验：同一 D，关闭/打开成熟反馈，来源与模型保持不变。
候选反馈只包括截至当时过去 28 个完整日的偏差、覆盖和来源可靠性统计；冷启动明确为无统计。
窗口、可读字段、对来源选择的作用及停止规则须在新分支单独冻结，不在当前轮择优。
反馈资源也向 B/C 提供同等访问权限，并设置固定反馈利用对照，不能把 D 独占误差信息归因于自主性。
若反馈只用于解释而最终输入不变，应如实报告没有预测作用；若需要拟合残差幅度，则不属于
本轮严格免任务训练方案，必须重新定义研究范围，不能悄悄作为在线学习加进去。

12. 最小实现与必要验证：避免防御性编程

复用：r9 的公共历史/日历/评分、真实 deadline、按目录一次性发布；M0 的原始源解析和接收记录；
M1 的先裁可见前缀逻辑。旧代码保持可重放，新候选实现单独的、名称明确的入口。
不照搬 M0 的 legacy demand_std/十项日历输入，也不直接把其合成响应输出当 r9 基线。

建议最小模块范围（均为未来计划，本分支未创建）：
- forecasting/agent_forecasting/totaldemand_information.py：来源选择、小时映射及唯一候选构造。
- forecasting/agent_forecasting/forecast_ledger.py：预测、标签及成熟状态追加记录。
- forecasting/agent_forecasting/evidence_policy.py：S2 时再实现 B/C/D 获取策略。
- scripts/run_totaldemand_information.py、audit_totaldemand_information.py：S1 配对执行与独立评分。
- 阶段专用配置、测试、协议和结果报告；不新建通用多 Agent 平台或插件系统。

边界校验只放在外部来源、时间、输入张量和持久化发布处；内部使用明确类型与一个主路径。
不广泛捕获 Exception 后静默用默认值，不层层重复验证，不新增多重重试/自动修复链。
保留一个明确 A 回退是预先定义的实验臂行为，必须暴露失败状态，不能把失败伪装成有效决策。
产品 schema 变化应显式报“不支持该版本”，在独立适配中处理；不锁死无关列的顺序制造脆弱性。

必要测试覆盖真实错误风险：
T1 时间：AEST 无 DST；period end→小时；25 步间隔与最终 24 步对齐；起报前完整接收。
T2 版本：先过滤可见前缀；同 target 不同 run；晚到修订；缺一半小时不能被静默填充。
T3 映射：A/B 历史与日历相同；B 仅增加同一物理需求未来通道；单位一致；无未来真实值。
T4 泄漏：未来标签与未成熟误差不能经输入对象、工具或提示词到达预测端。
T5 发布：真实超时使未发布预测无效；已完成 A 回退留在评分；半成品不能被审计当作发布结果。
T6 评分：手算小样本验证 QS/覆盖/回退权重，日期块/地区/seed 同步；独立重算实际预测表。
真实数值接口 smoke 最多选首个预定合法单元做 A/B 各一次，验证形状和映射，不据输出好坏改方案。
只跑相关既有回归与新增关键测试；没有代码变化的计划分支不运行模型或全量测试。
