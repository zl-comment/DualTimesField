R21 single-LightGBM input Agent: 181-origin development result

Status

The R21 implementation and three-region seed-2026 development replay are
complete. All 543 requested calibration origins were atomically committed and
scored. There were zero failed origins, zero fallbacks and zero API failures.
The 2023-2024 test split was not used.

Result

The primary region-equal five-quantile score did not improve:

- frozen LightGBM identity: 39.27788454 QS;
- R21 Agent: 39.27851438 QS;
- paired delta, Agent minus identity: +0.00062983 QS, or +0.00160%;
- seven-origin circular moving-block bootstrap 95% interval:
  [-0.01251607, +0.01282443];
- bootstrap probability that the Agent improves QS: 0.4401.

This is a development result and does not justify a formal-test superiority
claim. R21 v1 should not be promoted to the 2023-2024 evaluation yet.

What the result says about the architecture

The one-predictor constraint now holds. Every numerical candidate uses the
same frozen seed-2026 LightGBM checkpoints. Chronos is absent from the runtime,
manifest and candidate registry. The only differences are the immutable input
operation receipts. Kev cannot create a feature, retrain a model, read a future
target or submit a candidate that was not diagnosed on the locked cohort.

The two-stage gate also works as intended. The protocol first materializes the
finite development-admitted operation set and recomputes all candidates on one
fully mature cohort. Kev Stage A then chooses identity versus changing input.
Only after Stage A authorizes a change does Kev Stage B select the 24-hour or
48-hour demand-history operation. With no mature cohort, fewer than three
common successful episodes or any diagnostic failure, identity is mandatory.

The failure is now localized to selection quality. Across the 543 origins,
the hindsight oracle selected a nonidentity candidate 284 times and achieved a
region-equal QS of 39.06353576, 0.21434878 below identity. This oracle is not a
valid policy, but it shows that the materialized candidates sometimes contain
useful conditional alternatives. Kev matched the exact oracle candidate 245
times, compared with 259 matches from always choosing identity. In QLD1 and
TAS1, the learned choice head therefore reduced exact oracle agreement even
though QLD1 happened to gain slightly through error magnitudes.

Input-operation claim boundary

The two nonidentity candidates are explicit training-normalization-mean
counterfactuals. They neutralize older realized-demand cells while retaining
the fixed 1,465-dimensional schema. They are not native missing-value masks,
column deletion or literal shorter tensors. A stricter requirement for true
mask/profile semantics needs one LightGBM trained once with explicit profile
support and then frozen; this current experiment cannot make that claim.

Next optimization target

Keep the predictor, registry, cohort lock, replay, resume and operation set
fixed. Improve only the versioned evidence and decision skills on development
data:

1. measure which paired cohort statistics actually predict current operation
   benefit, instead of asking Kev to infer the mapping from verbose aggregates;
2. add calibrated abstention thresholds so weak or contradictory evidence
   resolves to identity;
3. distinguish the 24-hour and 48-hour hypotheses using recent demand-regime
   features and candidate disagreement;
4. test these changes on a later untouched calibration holdout before opening
   the formal test split;
5. after the decision modules are fixed, run module and skill ablations.
