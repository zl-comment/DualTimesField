R18 完整预测 Agent：设计计划与测试计划
日期：2026-11-03，Asia/Shanghai
状态：PLAN_ONLY。本文定义下一版系统，不表示模块已经实现或实验已经通过。
设计基点：a3a00e0e20bb88c5b554d4f05e2976c4f95090be，当前 R17 分支。
本次只编写计划，不启动预测，不恢复已停止的 R17，不修改现有主表。

1. 开发顺序与目标

按照用户要求：完整系统设计 → 模块实现与工程测试 → 完整闭环验收 → 整体实验 →
模块增加/删除/替换及 skill 优化 → 冻结最终版本与确认实验。
不把“每个模块先独立超过基线”作为建设完整 Agent 的前提。
工程测试回答系统是否正确执行；研究实验回答整个系统是否有效、哪些组成有贡献。
研究对照与消融在完整系统可运行后执行；无需重新设计或训练现有主表基线。

目标：以冻结预测器和 API 决策模型为基础，利用时点内可用的数值、事件、相似历史及
已成熟误差，主动决定需要哪些证据、输入范围、候选预测和组合，输出可审计的24小时预测。
不训练 Kev，不微调预测器，不拟合新的预测/残差/校准网络；开发更新的是代码、流程、
检索规则、动作注册表和项目 skill。既有 LightGBM 曾经过任务训练，不能称为零样本模型。
“越来越精确”是跨开发版本的研究目标，不是每次反馈后误差必降的产品保证。

R17 的实测只说明当前 Kev 决策最终等于 FIXED；不能据此删去尚未完整实现的 Agent 能力。
R18 不继续沿用“先强制数值规则确定唯一赢家，再让 LLM 重复选择”的决策结构。
但仍由程序限定数据权限、输入合法性、预算和输出格式。

2. 系统边界与默认模型

地区：NSW1、QLD1、TAS1。目标：从 origin 开始直接预测24个小时。
输出：五分位数 [0.05,0.10,0.50,0.90,0.95]，raw RRP，与既有评分一致。
时间：内部 Unix UTC；实验交易时间统一按既有固定 AEST UTC+10，不混入夏令时。
默认预测器计划采用现有已训练、已冻结的 LightGBM；Chronos-2 为异构候选。
这是 R18 的设计默认值，尚未完成接入；保留 Chronos-only 配置便于复现 R17。
预测器加载器核对已有 checkpoint、特征 schema、变换和版本，不重新训练。
Kev 继续使用 GPU6 的本地 System One API；Chronos 使用 GPU7，LightGBM 在 CPU 推理。
无需为本计划部署新的 LLM。若未来确需自由文本抽取，作为独立新版本再接入相应 API。

3. 总体执行图

输入快照及成熟反馈 → 状态摘要 → Kev 规划下一步
                                   ↓
       信息检索 / 公告解释 / 相似历史检索 / 候选预测 / 误差诊断
                                   ↓
                            工具观察更新状态
                                   ↓
                 Kev 决定补查、评审、提交或保留默认
                                   ↓
              程序校验 → 输出预测及引用 → 写入预测台账
                                   ↓
           真实值按时间陆续可用 → 成熟反馈台账 → 后续 origin

另有与上述推理隔离的评分器，负责计算整体实验和模块实验结果。
本次规划的“多模块”是一个控制器调用多个工具，不是部署多个自治 LLM 代理。

4. 模块清单和职责

M01 时间快照与数据访问
复用 R17 Snapshot 和既有 asof 思路，扩展为不可变 ForecastContext。
输入包括 region、origin、cutoff、公共72小时历史、已知未来日历、数据缺失标记。
来源入口返回带可见时间和版本的记录；先按权限与 cutoff 过滤，再检索或排名。
LLM 只收到当前快照和工具返回的白名单字段，不接收全年数据文件路径。

M02 状态与数据质量诊断
工具计算价格水平/波动、需求变化、跳变、缺失、异常、近期成熟误差与区间覆盖。
Kev 对状态和所需证据作选择判断；计算、单位换算和统计量由 Python 完成。
状态是有引用的观察摘要，不把“尖峰”“关系变化”等标签当作已证实的因果解释。

M03 数值及文档证据检索
统一接口 search_evidence/read_evidence，返回证据ID、源版本、发布时间、有效区间、
摘要及引用。规划覆盖市场公告、停机/恢复通知、天气或负荷预测的历史发布版本。
复用本地历史来源审计材料。旧归档仅有 LASTCHANGED/归档时间代理的，标注 archive_proxy；
不能把它升级为真实公开时间已核验。真实历史新闻覆盖率目前未知，实施时先盘点。
离线实验使用被冻结的历史证据仓；不把今天搜索到的网页直接当作当年可见版本。
若没有合格来源，模块返回 unavailable，完整系统须在结果中列出该能力未实际启用。

M04 事件理解与版本关系
现有 Kev 返回 typed choice，按步骤选择事件类型、相关区域、状态、相关性和证据ID。
原文片段、数字、单位、时间由解析器抽取并保留引用；Kev 从候选中选择或弃权。
M04 不假定 Kev 能自由生成长篇理由或任意 JSON；复杂正文解析不全时返回 unknown。
保留“已生效/计划/撤销/替代/冲突未解”。撤销或替代关系也须在 cutoff 前已可见。
通知中提到未来计划有效时间可以合法使用，前提是该通知版本在 cutoff 前已发布。
事件没有可靠数量映射时，只影响检索与候选选择；不得据文本编造电价修正幅度。

M05 历史相似样本与多样性检索
检索单位为 HistoricalEpisode：72小时历史＋24小时已成熟结果＋来源时间＋状态摘要。
首先保证 episode 的结果完整可用时间不晚于当前 cutoff，再按相似性找候选。
初始工具候选最多32条，返回给 Kev 的小包不超过8条；按特征距离、日期、状态去重。
可选检索方案：近期相似、季节相似、波动/需求状态相似、事件相似、兼顾多样性的混合。
Kev 选择检索方案或候选ID组合；程序保证不可选择未来、不重复、不超额。
样本多样性控制同日/重叠片段过多，以及样本全来自单一状态的偏置。
相似样本用于评估候选预测器在类似状态下的误差、稳定性和区间表现。
不得把不连续历史片段拼成一条假连续时间序列，也不得把样本追加进 LightGBM 当作训练。
初版不声称实现 Chronos few-shot：若后续模型接口确实支持，另作单独 adapter 和版本。
没有足够成熟样本时明确低支持度，保留原始预测路径，不能用真实未来补齐。

M06 冻结预测器与输入方案注册表
LightGBM：仅使用其原始训练特征结构、变换和已有 checkpoint；不通过删列或任意填零
模拟少特征专家，不接受未训练的新事件字段。支持复用与输入指纹匹配的已保存预测。
Chronos：允许预注册的 price_only/calendar/base，以及24/48/72小时历史窗口。
所有窗口都是当前公共72小时的子集；未来目标一律24小时，不改变目标轴。
数据源型新协变量只有在语义、单位、历史/未来映射和接口经过验证后才能注册；
否则事件只用于选择已经存在的候选，不悄悄进入数值输入。
每个候选的 forecast_id 绑定模型、输入、截止时刻、profile、窗口和输出 hash。
初始每个 origin 最多物化5个不同候选，包括默认预测；重复请求命中同一快照缓存。
候选缓存包含完整输入与权重指纹，不允许跨 release 误命中。

M07 诊断与候选评估
保留 R17 的历史内回测，但标注其48→24诊断与72→24正式预测的差异。
LightGBM 不能用48小时输入硬套72小时训练 schema；它的诊断使用完整、已成熟的历史
ForecastContext 或已有因果预测台账，不补未来、不填假历史。
提供近期成熟误差、相似样本误差、分时段稳定性、覆盖/宽度、候选分歧、成本。
评估器返回支持样本数和缺失标记。不能把短窗口误差排名视为唯一合法选择。
历史样本×候选的诊断推理也计入预算，不能以“只是检索”隐藏数值模型成本。
历史诊断区分当时实际发布的预测与事后重算。重算须检查模型训练数据是否包含该片段
的结果；训练内误差不作为无偏泛化证据。模型选择期样本也标明选择偏差，不能冒充
在线留出误差；模型/变换版本最迟须在当前决策cutoff前确定。

M08 Agent 控制器
控制器状态：目标、默认预测、已获取证据、历史样本、已生成候选、诊断、预算、决策链。
每次 Kev 调用选择白名单 action；action 参数通过下一步有界 choice 或模板补全。
一条 action 必须包含已有对象ID；宿主程序校验后才执行。
优先将模型/profile/窗口组合编译成一个action模板ID，避免每个参数消耗一次API。
需要多个独立字段时可在同一origin状态中请求多个typed choice；不得合并不同origin
的状态以节省调用，从而造成信息越界。
动作包括 inspect_state、search/read_evidence、resolve_event、retrieve_analogs、
request_forecast、compare_candidates、review_decision、commit_default、commit_candidate、
commit_pool、abstain。重复无新增信息的动作会被拒绝并记录。
初版最多8次API调用（重试也计入），最多12次工具执行，单请求最多24,000字节。
默认计划先提供状态摘要，再由 Kev 决定补什么信息；不强制每个实际样本调用所有工具。
8次调用预算下，工具响应需压缩为有证据引用的结构化摘要；不将长篇文档反复全量发送。

M09 决策复核与数值提交
结构检查由程序强制：时间可见、输入合法、模型版本一致、候选存在、分位数有限、
目标轴正确、调用预算合规。通过这些检查不等于准确性一定更高。
独立 review skill 可检查建议是否与证据矛盾、样本太少、事件有冲突或遗漏默认方案。
选择其他模型/输入不要求必须等于近期最小QS；R17的2%硬预筛和固定0.55阈值不直接继承。
初版用明确 abstain 动作及支持度标记，必要的阈值在开发阶段定义并冻结；API动作概率
只记录为模型选择强度，不当作预测准确率或收益概率。
提交可以选择一个候选，或使用注册的两候选分位数池化配方：权重0.25/0.50/0.75。
池化定义为排序后的同分位数加权和；这是分位数池化，不声称是混合分布的精确分位数，
也不保证覆盖率或校准。LLM只能选配方ID，不能生成任意权重或直接改电价。
最终返回预测数组、选中模型/输入/样本/事件ID、决策动作链和由模板生成的简短说明。

M10 成熟反馈与记忆
区分三类状态：当前origin工作区；按时间追加的预测与结果台账；版本固定的skill。
前两者可以随真实时间推进更新；正式评估时 skill、阈值、检索规则和更新算法保持固定。
只有全部所需结果已观测且已可用的历史预测，才可参与24小时整体误差统计。
需要部分成熟反馈时须单列 horizon 并明确分母，不能与完整24小时误差混算。
离线回放由时间服务逐步释放历史观测，Agent不直接读取整份test标签文件。
后验真实结果只能生成对应历史时段的误差记录，不能修改当时已发布的预测、事件或状态。
每个实验臂拥有隔离台账；同等信息对照可得到相同可用观测，但不读取其他臂的私有动作。
并行 origin 任务必须固定 memory watermark；按cutoff建立只读快照，不能因完成顺序
或未来任务提前结束而让较早origin看到较晚结果。先做顺序回放验证，再扩大并行度。

M11 运行、缓存与观测
复用 R17 分片、hash、恢复与评分模块，新增 evidence/memory/profile 指纹。
自动回退链：可用的默认冻结预测 → 已验证的同快照默认缓存；无合法预测则标记失败。
失败origin不从评估分母静默剔除，记录覆盖率、失败原因和可评分范围。
记录 LLM calls/tokens/耗时、数值推理次数、缓存命中、候选选择、工具调用、弃权、回退。
任何模块接入后要能在 trace 中看到真实执行和它影响的对象，不能以 prompt 中提过该模块
就宣称“完整 Agent 已使用它”。

5. 数据对象与接口约定

ForecastContext: region, origin, cutoff, history, known_calendar, availability_mask,
                 source_snapshot_id, memory_watermark, common_input_hash。
Evidence: evidence_id, source_id, version, published_at, first_seen_at(可空),
          availability_basis, valid_from/to, region, payload, content_hash。
EventFact: event_type, status, region, evidence_id, quote_span, related_versions,
           explicit_quantity/unit/time(可空), validation_status。
HistoricalEpisode: episode_id, history_start/end, target_end, outcome_available_at,
                   state_tags, similarity_fields, original_forecast_ids。
ForecastRequest: model_id, context_id, profile_id, window_hours, evidence_mapping_id。
ForecastArtifact: forecast_id, origin_axis, target_axis, quantiles, model/input hashes。
Diagnostic: candidate_ids, episode_ids, metrics, horizon, sample_count, missingness。
Action: action_id, arguments_from_registered_ids, evidence_refs, status。
DecisionTrace: release, context_id, requests/responses, observations, selected_forecast,
               fallback, budgets, timing, input_scope。
所有对象验证 schema；LLM 可选ID，不能改 cutoff、availability 或原始事实。

6. 项目 skill 设计

这是电价预测项目的运行时 skill，不是安装给 Codex 的全局 skill。
每个 skill 有 instructions.txt、schema.json、examples.jsonl、version、内容hash。
schema 约束最终对象；Kev typed-choice 适配层负责把它分解为合法的有界问题。
初始 skills：
S01 plan_forecast：选择下一步动作及停止条件。
S02 assess_state：解释数值状态、发现证据缺口。
S03 interpret_evidence：选择事件类型、相关区域、版本关系、未知项。
S04 retrieve_analogs：选择相似性侧重点和样本多样性策略。
S05 compose_forecast_request：选择模型、profile、窗口及已验证的输入映射。
S06 compare_candidates：结合近期/相似样本诊断提出单候选或池化配方。
S07 review_and_commit：检查证据支持、处理冲突、提交或弃权。
成熟误差更新由程序执行，初版不让 LLM 自由总结后改写自身 skill 或生成永久事实。
示例只使用合成案例或开发期材料，不从已暴露的测试期提取赢家规则写进 prompt。

7. 信息如何真正改变预测

数值状态 → 选择不同profile/历史窗口 → Chronos输入变化 → 预测变化。
事件证据 → 调整检索标签/候选优先级 → 选择其他冻结预测或池化配方 → 预测变化。
相似样本 → 相似情景下候选误差评估 → 候选选择变化 → 预测变化。
成熟反馈 → 最近误差及记忆索引更新 → 后续origin的候选评估变化 → 预测变化。
已有结构化未来协变量 → 经过注册映射与可见性检查 → 支持该字段的模型输入变化。
每条链路均有因果追踪：证据ID→动作→候选/输入hash→最终数组。
没有改变可执行动作的解释文字不算预测干预；没有合法映射的新闻不直接改数值。

8. 工程测试计划：先完整可用，再研究收益

T0 静态契约检查：对象schema、模型能力、skill注册、预算、配置和版本身份。
T1 单元/性质测试：截止时刻、公告版本、成熟反馈、检索排除未来、候选输入结构、
   不连续样本不拼接、数值池化、有限输出、幂等缓存、越权动作拒绝。
T2 接口集成：真实Kev、Chronos、LightGBM；有证据到预测变化的完整可追踪路径。
T3 场景端到端：平稳、尖峰/状态变化、公告撤销冲突、样本不足、来源缺失、API故障、
   断点恢复、分位数交叉、成熟反馈跨日、并行顺序扰动。
T4 开发期回放与稳定性：先三地区×24起点开发smoke，再三地区×181个按日间隔起点。
   多轮真实API重复、顺序/并行一致性、资源监测；不得只看一次synthetic结果。
T5 整体准确性与正式研究实验：在T0–T4可运行后进入，见第10节。

完整验收标准：
- 时间/版本/目标轴等硬约束测试零违反；发现违规即工程失败。
- 默认预测可复现原始对应预测；其余模型输出形状与单位符合契约。
- 每个模块在至少一个合成边界场景中被覆盖，有可验证输出和下游作用。
- 有真实来源的模块通过至少一个真实来源集成案例；没有真实历史数据的模块明确
  标为 real_data_unavailable，不能把合成测试通过写成真实历史接入完成。
- 正常开发运行中无未处理异常；故障注入测试能完成指定回退且保留任务。
- 输出覆盖、回退率、延迟、token、内存和预算全部可观测，不隐瞒模块不工作。
- 核心模块工程验收不要求逐个产生正的预测收益，整体也不因单个模块负收益就阻止验收。
测试明细另存 r18_test_matrix_20261103.csv，逐项记录 NOT_RUN/PASS/FAIL/UNAVAILABLE。

9. 预算与性能测试初值（开发期可修改，实验冻结后不可隐改）

每origin：最多8次API调用（含重试）、12次工具执行、5个不同当前候选、8个历史样本。
历史诊断最多40个 candidate×episode 推理单元；缓存可降低实际推理量但仍记录逻辑请求。
单API超时30秒，origin总截止180秒，超时使用已生成的默认预测，预算余额不足不再发起。
工具超时取单工具限额和剩余origin预算的较小值，不允许多次超时累积越过总截止。
API初始并发2，Chronos使用已有验证批处理；以真实服务测吞吐，不假设PyTorch路径支持
高效批量LLM。不得未经验证改变Kev内核、精度或服务实现。
开发性能验收报告 p50/p95/p99 与估算全量时间。能力与时延矛盾时在开发阶段调整预算，
不是让长任务无限运行。已测R17吞吐仅为参考，不能套用于更复杂R18。
正式三地区×三seed原网格为157,689个origin/repeat，8调用上界为1,261,512次API请求。
完整能力测试、开发回放和成本估算完成后才发起这一规模，不能先跑几十小时再发现
工具从不被选择或输出始终等于默认。这个要求验证执行覆盖，不要求单模块先证明增益。

10. 研究实验计划与版本优化

E0 完整Agent v1整体开发实验：全部模块开启，三个地区，同一冻结候选池。
先报告总体预测、成本和实际模块使用情况；完整Agent不以单模块收益筛选作为构建前提。
若模块缺真实来源，同时报告完整设计中的未启用项与可运行子配置，名称不能混淆。

E1 整体比较：复用原默认基座、R17/FIXED参考及已有主表；增加同等证据/候选池的确定性
全流程对照。对照实现是完整Agent后的评估组件，不扩展成新基线训练工程。
另设“始终单一候选”诊断以区分输入配置改善、候选库扩大与Agent选择改善。

E2 逐模块删除：去事件理解、去相似样本、去多样性、去成熟记忆、去输入范围控制、
去跨预测器路由、去池化、去review、LLM规划换固定流程。
模块关闭采用明确neutral行为，保持快照、预测目标、评分和其余配置一致。
例如去检索采用预定近期样本，去多样性仅保留相似度top-k，去记忆仅用当前快照，
去路由固定默认LightGBM，去池化只能提交单一候选。所有语义在运行前写入配置。
报告完整系统与删模块的总体效果和实际计算量；预算上限相同不代表实际调用成本相同。

E3 有针对性的增加/替换与skill优化：依据E0–E2定位问题，再比较一组版本；
允许联合优化，但须记录同时改变了什么，不能把联合变化归因给一个模块。
priority：工具可达性与使用 → 数据/诊断质量 → 决策表达 → skill示例/指令 → 预算。
检测模块交互时，挑选少量有解释的问题做二因素组合；不默认穷举全部开关。
所有这些迭代均放在开发期，生成不同release；不在同一正式运行中热修改。

E4 冻结最终完整Agent，再做确认及主表参考排名。
主指标QS，补充MAE、地区平均pooled RMSE、coverage90、width90、按地区/年份/月及
预先定义状态分组。报告模型/Agent训练成本区别、API和数值推理预算、失败分母。
时序配对不确定性采用时间块重采样，不能把重叠预测或确定性seed重复当独立样本。
seed沿用2026/2027/2028；Kev argmax无采样seed，明确其重复性含义，不能人为制造随机性。
主表按现有顺序：先三地区等权，后跨seed均值及样本标准差(ddof=1)。

11. 数据划分与公平解释

现有2022H1 selection 作为模块建设、skill优化与完整开发回放的主要范围，明确其已用史。
2022H2在仓库中曾参与其他方法校准，不自动称为全项目未见验证集；使用前盘点暴露记录。
2023–2024已用于R12等历史版本和R17，不再作为全新未见测试集。
可以在这两年做冻结版本的主表对齐回顾性比较，但不能用“再次换seed”恢复盲测性质。
如果需要独立确认，先盘点确未用于开发的后续时间段或新地区；具体边界须依实际数据
可用性及使用记录确定，本计划不伪造一个已经存在的未见集。

完整Agent可以使用超出72小时的成熟样本与证据记忆，但这是信息范围扩展：
- common-input配置：限制到原公共输入，不启用外部证据及长历史检索，作为兼容对照。
- full-evidence配置：使用有时间约束的文档/检索/反馈；主表可作同目标参考，但明确额外信息。
相同信息比较要求确定性对照也能访问同样的证据池、成熟台账和候选库。
固定预测器无新增训练不意味着所有方法历史训练成本相同；不同信息组不包装成严格等预算。
已知旧数据公开时点只是代理的部分，保留该限制；新增来源的严格时间过滤不能反过来
证明整套旧基准历史输入在当时都真实可获取。

13. 完成定义

完整设计完成：模块、数据契约、预测影响链路、skill、预算、测试及实验顺序明确。
完整实现完成：全部核心模块有代码和工程测试，真实模型闭环通过，依赖来源状态透明。
完整实验完成：预定完整Agent、整体比较、所选消融及冻结确认均有可重现结果。
这三个状态分别报告，不把“架构写完”“跑通一次”“全量评估完成”混为一谈。
