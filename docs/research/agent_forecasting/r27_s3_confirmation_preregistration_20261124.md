## 3. 规则冻结规格（全部只用 pre-2023 数据定义）

### 3.1 状态桶

- 桶特征：该起点的预调度 24 小时需求均值
  `bucket_feature(t) = mean_{h=1..24} predispatch_total_demand_mw[t, h]`，
  vintage 为"发布时间 ≤ 起点"的最新预调度 run（与基线同一 as-of 规则）。
- 桶数 4；边界 = **pre-2023 选择期**上该区域 `bucket_feature` 的四分位点
  （25/50/75 百分位）。选择期定义沿用主表协议：`2022-01-01 → 2022-07-01`。
- 边界为**逐区域**三个标量，共 9 个数，在运行前写入配置副本并在结果文档中
  逐一列出。
- 分桶规则：`b = 0,1,2,3` 对应 `(-inf, q25), [q25, q50), [q50, q75), [q75, +inf)`。
- 缺失处理：若某测试起点的预调度 vintage 缺失（已核实为 0 例），该起点
  **退回 R0**，并在结果文档中计数披露。不加 try/except 兜底层——若实际
  出现非零计数，先修原因。

### 3.2 准入

对每个区域、每个桶，成员 `m` 获准的条件：

```
QS_selection(m, region, bucket) <= 1.25 * QS_selection(lightgbm_seed2026, region, bucket)
```

- `QS_selection` 在 **pre-2023 选择期（2022H1）** 的该区域该桶起点上计算，
  口径与 §5 评分器完全一致。
- **【项目方技术修正】选择期成员预测的来源**：主表档案只有 `test.npz`，
  无选择期分片。正确来源为 **R25 折 C 的选择期档案**
  `outputs/forecasting/r25_ceiling_20261119/C/{REGION}/{cell}/selection.npz`
  （lightgbm×3 seed、xgboost、chronos2 均在，2022H1，每区域 721 起点、
  每日 4 个抽样子样）。口径披露：选择期 QS 在 4 起点/日子样上计算，非
  全小时频——这是零重训约束下的既定事实，不是本轮的选择。
- LightGBM seed 2026 按定义恒获准（比值 = 1.0），保证每桶至少一个成员。
- 准入结果是 3 区域 × 4 桶的成员名单，共 12 个集合，**运行前固化并在结果
  文档中全列**。
- 若某成员缺 R25 选择期档案，则该成员在**所有桶**不获准，并披露
  （当前五个成员均在档，预期 0 例）。

- 不按测试期任何统计调整桶边界、桶数、准入倍数 1.25、成员集合；
- 不做"算完看一眼再改 1.25"的任何动作。

## 4. 组合规格与对照臂

### 4.1 S3（主确认臂）

对每个区域、每个起点 `t`（落入桶 `b`）、每个小时 `h`、每个分位 `τ`：

```
S3[t,h,τ] = median_{m in admitted(region,b)} member_m[t,h,τ]
```

- 逐分位独立取中位数；成员数为偶数时取两中值的算术平均。
- 取完中位数后对 5 个分位做**非降排序**（与主表 `point_definition =
  sorted_q50` 口径一致）；记录排序前后发生交叉的格子比例作为描述量。
- 零可训练参数。

### 4.2 R0′（强制对照臂，与 S3 同时判分）

```
R0'[t,h,τ] = median(lightgbm_2026[t,h,τ], lightgbm_2027[t,h,τ], lightgbm_2028[t,h,τ])
```

无分桶、无准入、无跨族成员。它隔离出**纯同族 seed 方差缩减**的贡献。
开发折已量化（§2.1）：该成分占平静折 S3 增益的 56–76%。**S3 − R0′ 才是
跨族组合的真实增量。**

## 5. 评估协议（与主表同口径）

- 指标：`QS = 2 × 五分位平均 pinball`（主指标）；`MAE` 用排序后 q50；
  `RMSE`（pooled）、80%/90% 覆盖率与区间宽度为描述量。
- 聚合：先区域内对全部 17 521 起点 × 24 小时逐格平均，再三区域等权。
  **不抽样。**
- 评分器：复用主表共享评分器。运行时断言：
  1. 用该评分器对 `lightgbm seed2026` 重算，宏 MAE / 宏 QS 与主表
     `per_seed.csv` 对应行逐格一致（容差 1e-9）——**不一致即中止，
     修原因，不加容差**；
  2. 15 个成员档案的 `origin_unix` 与 `target_time_unix` 两两逐元素相等；
  3. 三个区域的起点集合一致（保证区域等权为严格配对）。
- 测试期：2023-01-01 → 2025-01-01（exclusive），与主表完全相同，不做任何
  子区间选择。

## 6. 预注册判定门（运行前冻结）

主估量：**区域等权 QS 改善 ΔQS = QS(R0) − QS(S3)**，R0 = lightgbm seed 2026。

### G-C1 主门（三条件全部满足方为通过）

- **(a) 幅度**：ΔQS **≥ 0.15** 且 **≥ 0.60%**（相对测试期 R0 的区域等权 QS）。
- **(b) 无区域重大受损**：任一区域 QS 恶化 ≤ **0.05**，MAE 恶化 ≤ **0.15**。
- **(c) 显著性**：DM + HLN 单侧检验 p < 0.05（§6.3），且 7 天分块 bootstrap
  单侧 p < 0.05 与之同向；两者不一致则记为"证据不一致"，不计通过。

### G-C2 解释性条件（与 G-C1 同时冻结，决定结论措辞而非通过与否）

**S3 − R0′ ≥ 0.05**（区域等权 QS）。

- 满足 ⇒ 可写"跨族组合在正式测试期带来可测增量"；
- 不满足 ⇒ 结论**必须**降级为"seed 平均有效，跨族组合未证"，即使 G-C1
  通过。

### 6.1 阈值依据

| 数值 | 依据 |
|---|---|
| 0.15 绝对 | 测试期 R0 宏 QS ≈ 24.19（主表）；0.6% × 24.19 = 0.145，与绝对门自洽取整 |
| 0.60% 相对 | 开发折平静期（折 A）实测 +1.81%；测试期为平静期、增益预期更小，取约 1/3 作安全边际 |
| 噪声下界校验 | 主表 LightGBM 三 seed 宏 QS sd ≈ 0.0049 ⇒ 0.15 ≈ 30 × sd，噪声无法过门 |
| 0.05 区域 QS 容差 | 锚定 R23 历史最佳产生过的最大单区域效应 0.0508，且 ≈ 10 × seed sd |
| 0.15 区域 MAE 容差 | 尺度换算：开发折 MAE/QS 水平比 ≈ 1.74，主表 LightGBM 三 seed MAE sd 0.0147 与 QS sd 0.0049 之比 ≈ 3.0 ⇒ 0.05 × 1.74 × (3.0/1.74) ≈ 0.15 |
| 0.05 的 G-C2 阈值 | ≈ 10 × seed sd：要求跨族增量本身超出 seed 噪声一个量级 |

### 6.2 不设"三区域同时严格改善"的全区域门

R25 已证该门对保守策略结构性不可能（不行动的差恰为 0 而非负），且 TAS1
历来平坦。改为"区域等权改善 + 无区域重大受损"，保留防单区域献祭作用，
不把不可能的门当结论。

### 6.3 显著性检验选型

- **主检验**：Diebold–Mariano (1995) + Harvey–Leybourne–Newbold (1997)
  小样本修正，**单侧**，HAC 方差（Newey–West，带宽按 h−1=23 的标准规则，
  运行前固定）。对象是 **S3 vs R0 这一对预先指定的配对**——这正是 DM 的
  合法适用情形。单侧的依据：假设方向在本文件中预先固定，双侧会损失功效
  且与预注册方向不符。
- **稳健性并列**：7 天分块 bootstrap（2000 次，块 = 7 天），与 R25/R26
  协议一致；理由是 24h 预测在小时频起点下窗口重叠，日块不足以覆盖序列相关。
- 逐区域 DM 作描述性报告，**Holm 校正**；不进入 (c)。
- **S3 vs R0′ 的检验**：两臂共享 3 个 LightGBM 成员，配对差高度相关，DM
  的渐近分布在此情形下可靠性下降。故 G-C2 用**分块 bootstrap 区间**判断，
  不报 DM p 值。*不确定标注*：高度重叠预测之间的检验校正方法不确定有公认
  标准做法，不编造文献；本方案的处理是只报 bootstrap 区间并明确披露重叠
  结构。
- **不对任何"取多者之优"的量报 p 值**（后选择推断，DM 无效）。

### 6.4 文献定位（只列有把握的）

Diebold–Mariano (1995)；Harvey–Leybourne–Newborn (1997)；组合谜题方向
Clemen (1989)、Smith–Wallis (2009)。EPF 侧"DM 为基准协议标配"按 Lago 等
人的开放基准（epftoolbox）理解，具体条目请自行核对。
