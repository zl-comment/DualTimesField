## 为什么这次不要求全量重训

针对固定 2015–2021 中位数填补的问题，逐个核对真实预调度文件和保存预测起点后得到如下结果。每格为单地区、单文件计数；三地区及预调度/联络线两类文件相同，不重复累计为独立样本。

| R25 折 | 训练 stale 小时 | 选择 stale 小时 | 评价 stale 小时 | 保存选择预测 stale/总数 | 保存评价预测 stale/总数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A | 0 | 0 | 0 | 0/721 | 0/733 |
| B | 0 | 0 | 0 | 0/721 | 0/733 |
| C | 0 | 0 | 739 | 0/721 | 123/733 |

C 的 stale 时段为 2022-10-01 10:00 至 2022-11-01 04:00（AEST）。C 的训练范围本就为 2015–2021；正式19基线也使用相同训练期。本次对六份已核实 SHA 的同训练折旧文件保留原填充值，避免重新估计引入舍入变化。

依据为保存的 `config_fold_A/B/C.yaml`、126 个实际选择/评价预测归档、六个 `data/aemo_exogenous/*predispatch*.npz`，以及历史 `cfe2a25` 的生成器实现。六个源文件 SHA 与正式基线 `aligned_baselines_20261012/jobs.json` 匹配。
R25 本身未找到独立的六份原始数据 SHA 清单，也没有重建全部历史输入比对 input_hash，因此这是特定缺陷的实际影响核查，不能写成历史全流程逐位复现证明。

四个基础模型固定的是已有归档的实际权重，不是更换模型。辅助分位仅作诊断，不进入主评分。
Moirai 起点修复已通过合成接口测试，但本次没有做真实模型修前修后等价推理，因此不把“预计只影响时间元数据”写成已经实测证明。
